# MP3 下载性能记录

2026-10-25，完成第一轮客户端与服务端下载优化。

## 实施内容

- 下载仍按章排队，章内默认 4 个文件并发；整章与现有经节 MP3 均保留。
- 界面和后台通知按所有活动文件汇总进度，字节事件每 200 ms 合并，进度事件复用文件集合与已完成大小。
- 下载检查点按 500 ms 或 8 个完成文件合并；暂停、章节完成、失败、删除和进入后台立即刷盘，写入始终串行，失败保留待写记录。
- 原生和 Web 的完整文件在恢复索引前检查真实大小和 SHA-256，空间不足也可复用已下载文件；损坏文件不能当作完成。
- 准备、入队、暂停、恢复、删除操作串行，防止删除期间重启任务或恢复过期资产。当前章出错会取消其余 worker，全部落定后再处理后续章节。
- 使用一致的章节空间准入预算，避免把正在增长的临时文件同时计入磁盘占用和完整预留；实际写入空间不足继续由平台适配器报告。
- 服务端下载清单的文件元数据检查最多 8 个并发，保留原接口、文件顺序、去重、有效性检查与目录更新行为。

## 测量方式与边界

在同一台电脑上使用 Node.js 24.3.0、相同线上音源和固定清单快照，对新队列分别配置并发 1 / 4，每个范围重复三次，取中位数。测试每轮使用新的临时目录，真实接收 MP3、校验 SHA-256 / 大小、写入临时文件与检查点，结束后清理。

这是新队列的串行/并发对照，用于观察真实网络请求下并发调度的收益；没有把旧客户端完整实现作为对照，也没有使用手机 Expo 文件适配器或真实浏览器 CacheStorage。表中耗时不含最初的清单获取、用户确认和设备启动时间。

阶段累计网络与校验时间可能重叠，不能相加当作总耗时。Node 基准的文件存储用于隔离现有数据；它不能代表真机的写盘、前后台调度与内存表现。

| 诗篇 23 英文 | 7 | 0.67 | 0.301 s | 0.111 s | 63.1% |
| 诗篇 23 中文 | 7 | 0.65 | 0.289 s | 0.116 s | 59.9% |
| 创世记 1 英文 | 32 | 3.61 | 1.323 s | 0.406 s | 69.3% |

另有固定 100 ms 请求延迟的自动回归：32 个文件串行耗时 3200 ms，4 并发耗时 800 ms；该结果仅说明排队算法行为。

## 下载清单

改动前从电脑重复请求现网清单三次，响应为 21,813,540 字节；首字节约 0.605～0.618 秒，总耗时约 2.05～2.18 秒。客户端音频并发收益不包含这部分准备等待。

本轮仅减少服务端串行文件检查，未修改清单契约或部署线上服务。清单体积和 JSON 解析仍可能影响手机上的准备时间。范围清单、按章打包属于后续单独评估项；打包本身不减少 MP3 音频内容的占用。

## 复现

默认测试不会访问线上服务器；网络基准必须显式开启：

```bash
SELAH_DOWNLOAD_BENCHMARK_URL=http://106.14.219.191 \
SELAH_DOWNLOAD_BENCHMARK_OUTPUT=/tmp/selah-download-benchmark-results.json \
SELAH_DOWNLOAD_BENCHMARK_BOOK=1 \
npm test --workspace @selah/app -- test/download-network-benchmark.test.ts
```

不设置 `SELAH_DOWNLOAD_BENCHMARK_BOOK=1` 时只测诗篇 23 与创世记 1 的中英文；设置后额外测创世记整卷中英文。全部范围各三次串行、三次并发测试，会下载数百 MB 以上数据，请在合适的网络环境下运行。清单在整轮开始时读取一次。
